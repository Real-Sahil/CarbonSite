# Calculation, factor libraries and formatting

Moved word for word out of CLAUDE.md so it is read only when working in this area (``lib/calculation/`, `lib/factors/`, `lib/country/`, `lib/i18n/``). CLAUDE.md keeps the rules that apply everywhere and an index of these files.

**Spend by industry:** a library whose factors carry `activityType` `naics_<code>` (EPA USEEIO 1.3), `naf_<division>` (ADEME spend ratios; a NAF code such as 41.20Z or 79110 matches on its 2-digit division) or `uksic_<group>` (Defra UK spend multipliers; a UK SIC 2007 code matches the group with the longest covering prefix, `groupPrefixes()` in `lib/factors/uk-spend.ts`) prices a record only through the record's own `industryCode`; without one those factors are excluded and the calculation says to add the code. When the run's library has no industry factor for a spend record that names a code, `selectSpendSupplement()` (`lib/calculation/spend-supplement.ts`) prices it from the spend library for the record's currency (GBP Defra UK multipliers, USD EPA USEEIO, EUR ADEME), naming that library in the selection reason; reports credit every library a run used (`runFactorAttribution()`, `lib/reports/attribution-load.ts`). A factor whose notes say "Unverified:" still calculates, with a warning on the calculation.

**Country profile** (`lib/country/profile.ts`, `countryProfile(hqCountry)`): a recommendation layer, never a lock. From the HQ country (normalised by `countryIso2()`) it gives the region (`uk`, `eu`, `uae`, `us`, `other`), the report types that lead the picker (UK: GHG Protocol, PPN 006, SECR, bid pack; EU-27: GHG Protocol and ESRS E1, E3, E5; UAE, US and others: GHG Protocol, CDP, TCFD structure, sustainability report; GHG Protocol is always first because every plan can generate it), the national factor library if one is loaded (GB, US, FR) and plain notes on what is and is not loaded. Used by the report picker (`recommended`, group label "Recommended for <country>") and under HQ country in Settings → Operations. Access is still decided only by plan (`requireFeature`, `requireCapacity`, `requireReportType`) and role (`requireOrgMember`); no report, library or page is hidden by country. Country also steers the default factor library (`defaultRunInputs()`), the 409 `LIBRARY_COUNTRY_MISMATCH` confirmation on runs, factor matching (`recordCountry()`), number and date formats (`localeForCountry()`), the regulatory calendar (`relevantRegions()`) and the address-search bias. To add a country's rules: add its region to `regionOf()`, its report list here, and its national library to `libraryCountry()`.

**No-factor records and gallons (methodology `ghg-protocol-v2026-03`, migration `20261005000067`):** a record that matches no factor (library or organisation) is still saved at 0 kg CO2e; the dashboard now says so in its own red alert (`noFactorCount` in `loadLatestRunStats()`), apart from other zeros (unit the factor cannot use, zero amount). `normalizeUnit()` takes the record's country as a fourth argument: a bare "gallon", "gallons" or "gal" is a US gallon (3.785 L) for US, PR, GU, VI, AS and MP records, an imperial gallon (4.546 L) for GB with no note and for other or unknown countries with a note ("enter US gallons if these are"); `NormalizedUnit.note` is added to the calculation's warnings by the run worker; "US gallons" and "UK gallons" are never reinterpreted; bare "gal" is accepted only for US records. **EPA Hub and eGRID (migrations `20261005000068`, `20261005000069`):** the EPA 2025.1 library now carries the Hub's fuels, steam and heat, freight, waste, travel, commuting and refrigerant tables and eGRID2023 rates (see the factor table). **eGRID subregions are never guessed:** a subregion row (activity type `egrid_<code>`) is used only when the record's fuel/detail text names its code ("eGRID CAMX") or its facility has `Facility.egridSubregion` set (Settings → Operations, shown for US sites, optional); every other US electricity record uses the national average row, which now sorts before the older stale `epa-2025-elec-us-lb-kwh` (0.3712, eGRID 2022) on an id tie-break (`pickEgridSubregion()`, `lib/calculation/egrid-subregion.ts`, `FactorQuery.egridSubregion`). Puerto Rico's only subregion (PRMS) is the PR country default. Category defaults for a record naming nothing: litres in stationary combustion take distillate No. 2, waste takes mixed MSW to landfill, a km record takes the average car, tonne.km the average truck. `mmbtu` is a registered energy unit. **Subregion suggestion** (`lib/calculation/egrid-locate.ts`, `GET /api/orgs/{orgId}/egrid-subregion?lat=&lon=`, `lib/factors/data/egrid-plants-2023.json` built by `scripts/build-egrid-plants.ts` from the eGRID2023 PLNT23 sheet): for a US site with coordinates the facility form suggests the subregion of the five nearest plants when at least four agree and the nearest is within 100 km, and the person confirms it; near a boundary it says so and points to EPA's Power Profiler (ZIP lookup), the authoritative check. **US residual mix** (`lib/factors/us-residual-mix.ts`): the Center for Resource Solutions' 2025 release (2023 data, adjusted system mix by subregion) is offered on the Electricity contracts form for a residual mix instrument, filling the rate and a citation; it is never applied silently, and update it each January. No licence or terms of use were found on the CRS page, which asks users to cite the rates. **US disclosure rules:** California SB 253 (Scope 1 and 2 first report due 10 November 2026 on CARB's updated proposal, Scope 3 and limited assurance from 2027, no CARB template or assurance in 2026) is served by the GHG Protocol report and assurance pack, and SB 261 (climate-related financial risk; enforcement enjoined by the Ninth Circuit in November 2025) by the TCFD-structure climate disclosure; both are on the regulatory calendar (region `us`, checked 4 October 2026, dates under court challenge). Not built, on purpose: an SEC report (the 2024 rules are stayed and the SEC proposed on 29 May 2026 to rescind them), EPA GHGRP reporting (facility-level to EPA via e-GGRT, under reconsideration since September 2025) and a CARB-format template (CARB's is not final). Recheck each quarter. **Known US gaps (not fixed):** mobile CH4/N2O by vehicle year (Tables 3 to 5) and CNG by volume are not loaded, there is no US battery-electric commuting factor (a "BEV" commute record takes the average car, now with a warning), refrigerant records that name no gas take an arbitrary HFC (with a warning), and EPA factors are AR5 while the methodology is AR6 (stated on reports, not restated). **Library fallback (methodology `ghg-protocol-v2026-04`, migration `20261005000070`, `lib/calculation/library-fallback.ts`):** on an EPA run, a record that matches no EPA factor in its category (not grid electricity or heat, which never fall back, and not one with an organisation factor) is priced from the DEFRA set for the period, then ADEME, when that factor's unit takes the record's unit; selection reason starts "fallback library" (the dashboard counts it as fallback kg), and the warning names the library and any other country's factor as a proxy. DEFRA and ADEME runs have no fallback. After the Hub load the EPA library covers nearly every category DEFRA does, so this triggers only for categories EPA lacks entirely (fuel- and energy-related activities, end of life, use of sold products); a category EPA has but whose units cannot take the record still gives a visible zero. **Selection cautions** (`selectionCaveats()`, `lib/calculation/selection-caveats.ts`): a BEV commute priced with an average car and a refrigerant record naming no gas each carry a warning. **GWP basis:** EPA and USEEIO reports state that gases are combined at AR5 (`factorAttribution()`); the factors are not restated to AR6.

**National libraries: Australia, Canada, Germany, Ireland (methodology `ghg-protocol-v2026-05`, migrations `20261005000071` to `20261005000075`; `lib/factors/{nga,eccc,uba,seai}.ts`, `national-load.ts`, `national-libraries.ts`, `pnpm tsx scripts/build-national-factors.ts <nga|eccc|uba|seai> <xlsx> <migration_name>`, workbooks in `data/sources/`):** "NGA Factors" 2025 (Australian National Greenhouse Accounts Factors, 159 factors: electricity by state plus national, residual mix, Scope 3 electricity, fuels, landfill, refrigerants; Creative Commons Attribution; gases at AR5), "ECCC" 2024 (National Inventory Report Annex 7, **electricity only**, 84 factors: consumption intensity by province and territory for 2019 to 2024, the latest year preliminary and open-ended; Open Government Licence - Canada), "UBA" 2.1 (Umweltbundesamt emission factor list, 578 factors: stationary, mobile, German mix electricity, heat, upstream, travel, freight, refrigerants; CC0 1.0, cite the source and say values were restructured, never changed; sheets 03, 10, 11, 12 and the biogenic "outside scopes" values are not loaded) and "SEAI" 2025 (68 factors: fuels and yearly electricity 2015 to 2025, **CO2 only**, sustainable biofuels at zero as SEAI states; the workbook states no licence, so SEAI is cited on every factor and report and this is recorded in `docs/THIRD_PARTY_SOURCES.md`). `libraryCountry()` maps them to AU, CA, DE, IE, so `defaultRunInputs()` picks them for an org in that country and a run on one for another country needs `confirmLibraryCountry`. **Regional grids** (`lib/calculation/regional-grid.ts`, activity type `grid_<cc>_<code>[_upstream]`, `Facility.region`): like eGRID, a state or province row is used only when the record's fuel/detail text names it (full names and places, never the abbreviation "on") or its facility's region reads as one ("NSW", "Ontario"); every other record in that country takes the national row, and another country's regional rows are never offered. Western Australia reads as SWIS with a warning unless NWIS is named. **Library fallback now covers EPA, NGA, ECCC, UBA and SEAI runs** (`FALLS_BACK` in `library-fallback.ts`): a record the library has no factor for is priced from DEFRA, then ADEME, with a warning; grid electricity and heat never fall back (an ECCC run therefore prices everything but electricity from DEFRA). **Factor hint matching** now requires the hint word to start a word in the factor's text, so "diesel" no longer picks "biodiesel". Calendar entries added 4 October 2026 from official pages: Australia (NGER report 31 October, AASB S2 Group 2 first report), Canada (GHGRP 1 June; CSDS stays voluntary since the CSA paused rulemaking in April 2025, so no date), Germany (BEHG report 30 April). Not loaded: Singapore (one EMA figure, licence unverified), NGA Scope 3 beyond electricity and upstream fuels. Update each year when the publishers release (NGA August, ECCC with each National Inventory Report, UBA irregular, SEAI annually).

**Country and currency at sign-up** (`lib/i18n/countries.ts`, sign-up and `/orgs/new`): the person picks the HQ country (no default) and the reporting currency follows it, editable. `POST /api/orgs` stores the ISO-2 country and the currency (their own, else `currencyForCountry()`, else the schema's GBP); an unlisted country or malformed currency is dropped rather than refused. Third-party terms are in `docs/THIRD_PARTY_SOURCES.md` (AIB residual mixes are not loaded: their terms bar use inside a derivative tool). **Financial year** (`lib/i18n/fiscal-year.ts`, `Organization.fiscalYearStartMonth`, migration `20260929000059`): asked at sign-up and in Settings → Operations; "Next financial year" on the reporting periods form fills label (`FY2026` or `FY2026/27`) and dates after the latest period. Periods stay free-form; nothing is derived from it. A per-entity override and entity setup at sign-up are not built (entities, ownership and control already live on the boundary page). **Group model (decided):** one organisation per reporting group, with entities and countries as filters inside it; a company that wants separate books gets a second organisation. The dashboard has entity (a legal entity and its subsidiaries) and country filters (`lib/dashboard/group-scope.ts`, `?entityId=&country=`), applied as the set of facilities they cover exactly like the contract filter; with either set the period comparison is suppressed. A per-entity financial year is not built: periods are one organisation-wide calendar, and it would only matter once group totals are consolidated across different year ends.

**Currency on web pages:** `OrgLocaleProvider` (org layout) now carries the organisation's reporting currency as well as its locale; client components call `useOrgMoney()` (`components/org/org-locale.tsx`: `format(n, {currency?, decimals?})`, `symbol`, `currency`) and server pages `getOrgFormat()` with `formatMoney()` / `currencySymbol()` from `lib/i18n/org-format.ts`. Done: invoice anomaly pages, TCFD (labels and amounts) and TNFD, offsets (new purchases default to the org's currency), MACC cost, contracts (each shows its own `currency`; a new contract takes the org's reporting currency when none is sent, so `createContractSchema.currency` has no default). **Stays GBP on purpose and labelled:** social value and National TOMs, PPN/CRP/SECR, tenders, billing prices, the contract carbon budget's `contractValueGbp`. Invoices have no currency column and are shown in the org's. **Supplier data form** (`app/supplier-data/[token]`, the link in every supplier request email and on the verify page): it used to post `quantity`/`description` to a route that wanted `totalAmount`/`calculationMethod`, so every submit returned 400. Units and method now come from one place (`lib/suppliers/units.ts`: tCO2e/kgCO2e are direct measurement, kg, tonne, kWh, MWh, litre, m3, piece are activity data, any 3-letter currency code is spend), the form sends `totalAmount`, `unit`, `notes`, the route (`POST /api/supplier-data/{token}`) works the method out when it is omitted, the accept step treats any currency code as spend, and the form offers the requesting organisation's currency first. Regression test: `tests/security/supplier-data-submit.test.ts`. A separate older flow lives at `app/public/supplier-data` (GBP, USD, EUR only). Dates on most web pages are still hard-coded en-GB.

**Worldwide formatting** (`lib/i18n/org-format.ts`, `docs/GLOBAL_READINESS.md`): `orgFormat()` turns `hqCountry` and `reportingCurrency` into a locale and currency, `formatters()` gives date, number, tonnes, money and percent for it. The sustainability report and the climate disclosure use it; the GHG Protocol, CSRD E1/E3/E5, CDP, contract carbon and transition plan reports take the organisation's locale through `withLocale()` / `loc()` (`lib/reports/templates/locale.ts`, set by the registry from `hqCountry`). **UK-form reports stay en-GB on purpose** (PPN 006, SECR, PPN 06/21, National TOMs, NHS Evergreen, the bid pack): their readers are UK buyers and regulators. Web pages still hard-code `en-GB` and GBP in places (see the readiness document). A figure kept in a fixed currency (National TOMs social value is GBP) says so in its label. New work formats through `formatters()` and never hard-codes a country, currency or regulator.

**Organisation commitments in reports** (`lib/reports/commitments.ts`, `loadOrgCommitments()`): PPN 06/21, NHS Evergreen, CDP, ESRS E1, SECR and the bid carbon pack take the net zero year, interim targets, measures, signatory, SECR efficiency measures, base year and internal carbon price from the organisation's records (the period's Carbon Reduction Plan, then the transition plan, then the latest plan; reduction initiatives; the active base year; `appraisalPrice()`), with report form options overriding. A value never recorded prints as missing, never a default such as "net zero by 2050". Market-based Scope 2 prints "Not calculated" when no record in the run was market-based (`hasMarketBasedScope2()`). SECR shows the previous period's latest snapshot beside this year's. The contract carbon report uses the contract's own GBP value for intensity. **CBAM is withdrawn**: the route answers 422 `REPORT_TYPE_UNAVAILABLE` because the platform records no import declarations (CN code, origin, tonnes, installation emissions); the old handler estimated them from purchased goods.
